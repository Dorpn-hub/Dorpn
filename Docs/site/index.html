Dorpn Language Documentation

● v0.4.0  ·  Pre-release

Dorpn is a statically-typed, compiled language with clean, indentation-based syntax. It compiles to C for native performance, and as of v0.4.0, also to JavaScript for scripting and rapid testing. Write once in .dpn, target two completely different runtimes.

Dorpn is designed for developers who want clean, readable syntax without sacrificing speed. It uses indentation-based blocks to define scope — readable by design — and compiles all the way down to a native executable through C and GCC.

ℹ This documentation covers Dorpn v0.4.0. The JavaScript backend is new — some features may only be available in the native C target. Existing .dpn files from earlier versions compile as before with no changes required.

// Why Dorpn?

  • Clean, readable syntax — Dorpn uses indentation to define blocks, keeping code visually structured without braces or semicolons. Less noise, more clarity.
  • Compiles to native C — Your .dpn code goes through a full compiler pipeline ending in a GCC-compiled binary. No interpreter overhead, no virtual machine — just fast, native code.
  • JavaScript target (v0.4.0+) — The same source file can now compile to JavaScript too. One language, two runtimes — native performance for systems work, JS for web and scripting contexts.
  • Static typing with clear declarations — All variables carry explicit types. Bugs that come from type mismatches are caught at compile time, not at runtime when users find them.
  • Minimal tooling required — A single dorpn binary is all you need. No package manager, no build system, no configuration file. Download and run.
  • Great for learning language internals — Dorpn's compiler is small and readable. If you want to understand how lexers, parsers, and code generators work, Dorpn is a concrete, real example to study.

⬇ Installation

Dorpn is currently available for Windows only. Download the latest installer from the Releases page on GitHub. Run the installer and Dorpn will be ready to use — no manual setup needed.

ℹ Other OS's support is planned for a future release. Source files use the .dpn extension — for example: hello.dpn

// Verify installation

dorpn --version

▶ Quick Start

Here is your first Dorpn program. Create a file named hello.dpn:

# My first Dorpn program
tag name: String = "Dorpn"
print("Hello from " + name)

Compile and run it:

# Compile to executable
dorpn hello.dpn

# Compile and run immediately
dorpn hello.dpn --run

# Compile, keep intermediate C file, and show verbose output
dorpn hello.dpn --keep-c --verbose

// A more complete example

tag x: Int = 10
tag y: Int = 20
tag result: Int = x + y

print("Sum: " + result)

if result > 15:
    print("Result is greater than 15")
else:
    print("Result is 15 or less")

T Types

Dorpn is statically typed. All variables must have a declared type. The built-in primitive types are:

Int
Default integer type. Used for whole numbers — counters, indices, scores.
tag x: Int = 42
Int32
Explicit 32-bit integer. Use when you need a specific 32-bit size guarantee.
tag x: Int32 = 99999
Float
Floating-point number. For decimals, measurements, and math calculations.
tag pi: Float = 3.14
Float32
Explicit 32-bit float. Use when memory efficiency matters over precision.
tag r: Float32 = 1.5
Bool
Boolean value — either true or false. Used in conditions and flags.
tag ok: Bool = true
String
A sequence of characters. Used for text, names, messages, and output.
tag s: String = "hi"
void v0.4.0+
A pass marker — tells Dorpn a function block intentionally does nothing. Not a type.
func greet(): void
# All Dorpn types in use
tag age:   Int    = 25
tag score: Int32  = 99999
tag pi:    Float  = 3.14159
tag ratio: Float32 = 1.5
tag name:  String = "Dorpn"
tag ok:    Bool   = true

≡ Variables

In Dorpn, every piece of data lives in a variable or a constant. Variables are how you give a name to a value so you can refer to it, change it, and pass it around your program. Dorpn has two declaration keywords that cover the two most common needs — values that change over time, and values that should never change once set.

Dorpn uses explicit declarations: you always say whether something is mutable or constant. This makes your intent clear to anyone reading the code, and lets the compiler catch bugs like accidental reassignment of something that was meant to stay fixed.

// Mutable variables — tag

Use tag to declare a variable whose value can be changed at any point after it is first set. The name comes from the idea of "tagging" a value with a label — you're giving a name to something that may need to be updated as your program runs. Counters, user inputs, running totals, and anything that evolves over time all belong in a tag.

tag <name>: <type>
tag <name>: <type> = <value>

// Constants — Const

Use Const to declare a value that is set once and never changes. The compiler enforces this — any attempt to reassign a Const will produce a compile error before your program ever runs. This is useful for things like version numbers, configuration values, colour codes, and any other value that has a fixed meaning throughout your program.

One important detail: Const is case-sensitive. It must be written with a capital C. Writing const in lowercase will not trigger a compile error — Dorpn will simply treat it as a regular variable name, which is almost certainly not what you intended.

Const <name>: <type> = <value>

// Examples

# Mutable variable — value can be changed
tag score: Int    = 100
tag name:  String = "Alice"
tag ratio: Float  = 0.5

# Constants — value cannot be changed after declaration
Const MAX_SCORE: Int    = 9999
Const APP_NAME:  String = "Dorpn"

# Reassigning a mutable variable is fine
score = 200
name  = "Bob"

-- Const reassignment would cause a compile error:
-- MAX_SCORE = 1  # ERROR
⚠ Const with a capital C is a keyword. Writing const (lowercase) will be treated as a normal variable name — not a constant declaration.

// Variable naming rules

  • Must start with a letter or underscore _
  • Can contain letters, digits, and underscores
  • Case-sensitive: myVar and myvar are different
  • Cannot use reserved keywords like tag, if, func, etc.

⇄ Control Flow

Control flow statements determine the order in which your code executes. They let you make decisions, repeat actions, and build logic into your programs.

// if / elif / else — Conditional branching

What they do: if checks a condition — if it's true, it runs the block. elif (short for "else if") checks another condition if the previous ones were false. else runs when no conditions match.

When to use: Use conditionals when you need your program to make decisions — like checking user input, validating data, or handling different cases.

if condition:
    # runs if condition is true
elif other_condition:
    # runs if first condition is false and this is true
else:
    # runs if all conditions above are false
tag score: Int = 85

if score >= 90:
    print("Grade: A")
elif score >= 75:
    print("Grade: B")
else:
    print("Grade: C")

// keep — Conditional loop (while)

What it does: keep runs a block of code repeatedly as long as a condition remains true. It checks the condition before each run — if it's false, the loop stops.

When to use: Use keep when you don't know how many times you need to repeat something — like waiting for user input, processing data until a condition is met, or running a game loop.

keep condition:
    # repeats as long as condition is true
tag i: Int = 0
keep i < 5:
    print(i)
    i += 1  # without this, it would run forever

# Infinite loop — runs until manually stopped
keep true:
    print("running...")

// loop — Counted iteration (for)

What it does: loop runs a block a specific number of times. It's used when you know exactly how many repetitions you need. You can use it with or without a counter variable.

When to use: Use loop when you need to repeat something a known number of times — like iterating over ranges, running a fixed number of tests, or processing items in a collection (once arrays are supported).

# Simple count — runs N times with no counter
loop N:
    # runs N times

# Named counter — i goes from 0 to N-1
loop i in N:
    # i is available inside the block
# Loop 5 times (no counter needed)
loop 5:
    print("Hello!")

# Loop with counter variable i (0 to 29)
loop i in 30:
    print("Step: " + i)
💡 Pro tip: Use keep when the number of iterations is unknown (like waiting for input). Use loop when you know exactly how many times to repeat (like processing 100 items).
ℹ Dorpn uses indentation to define blocks. Consistent 4-space or tab indentation is required throughout your file. Mixing spaces and tabs will cause a compile error.

ƒ Functions

Functions are the building blocks of any Dorpn program larger than a few lines. They let you give a name to a piece of logic, so you can call it from anywhere in your code without rewriting it. In Dorpn, functions are declared with the func keyword.

Functions that perform side effects and return nothing use void as a pass marker inside the body. Functions that compute and return a value use the return keyword.

// Syntax

func function_name(param1: Type1 ,param2: Type2) -> ReturnType:
    # function body
    return value

// Examples

# Function with no parameters — void means no return value
func greet() -> void:
    print("Hello from Dorpn!")

# Function with parameters and a return value
func add(a: Int, b: Int) -> Int:
    return a + b

# Function taking a String parameter
func welcome(name: String) -> void:
    print("Welcome, " + name)

# Calling functions
func _Start():  -- Entry point of Dorpn
    greet()
    welcome("Dorpn")
    tag result: Int = add(3, 7)
    print(result)

// void — pass marker

void is not a type in Dorpn — it's a pass marker. When placed inside a function block, it tells the compiler that this block intentionally does nothing. Think of it like pass in GDScript or Python. It's useful when you're stubbing out functions you plan to fill in later.

# void used as explicit empty body (no-op / pass)
func greet(n: String) -> void:
    void

# Once ready, replace void with real logic
func greet(n: String) -> void:
    print("Hello, " + n)

# Comments

Dorpn supports two styles of single-line comments. Both are equivalent — use whichever fits your style. Multi-line comments are not supported in the current version.

// Hash style — #

The # character starts a comment that runs to the end of the line. Good for quick annotations inline with code.

# This is a comment
tag x: Int = 10  # inline comment after code

// Double-dash style — --

The -- sequence also starts a single-line comment. Useful when you want to visually distinguish comments from code or when commenting out code that contains #.

-- This is also a comment
tag y: Int = 20  -- inline comment after code

// Both styles together

# Dorpn comment styles
-- Both # and -- are valid single-line comments

func add(a: Int, b: Int) -> Int:
    # add the two numbers and return
    return a + b  -- returns the sum
ℹ Multi-line block comments are not yet supported. For longer comment blocks, prefix each line individually with # or --.

⚡ Built-in Functions

Dorpn provides a set of built-in functions available in every program — no imports needed. For a detailed reference with additional examples, see the built-Ins_Functions.md in the Docs folder.

// Output

print(value) -> void

Writes output to the console followed by a newline. Accepts one or more comma-separated values — they are printed space-separated on a single line.

print("Hello, world!")
print("Value:", x, "Result:", result)
printOut(value) -> void  v0.4.0+

Writes output to the console without a trailing newline. Useful for building a line piece by piece — commonly used with ANSI color sequences for styled terminal output.

Const fgGreen = "[92m"
Const fgReset = "[0m"

printOut(fgGreen)
printOut("SUCCESS")
printOut(fgReset)
print(" - Build passed!")

// Input

ask(prompt?: String) -> String

Pauses execution and waits for user input. Returns the entered value as a String. Accepts an optional prompt string displayed before waiting. If no prompt is given, the program waits silently.

tag name: String = ask("Enter your name: ")
print("Hello, " + name)

-- Without prompt
tag raw: String = ask()

// Type Inspection

type(value) -> String

Returns the data type of a value or variable as a String. Useful for debugging or inspecting values that come from user input or dynamic expressions.

print(type(42))        -- Int
print(type(3.14))      -- Float
print(type("hello"))  -- String
print(type(true))      -- Bool

// Math

abs(value: Int | Float) -> Int | Float

Returns the absolute value of a number. Works with both Int and Float. Negative values are returned as their positive counterpart; positive values pass through unchanged.

print(abs(-10))    -- 10
print(abs(-3.14))  -- 3.14
min(...) / max(...)

min() returns the smallest value among the given arguments. max() returns the largest. Both work with Int, Float, and String — strings are compared lexicographically.

print(min(5, 10))               -- 5
print(max(5, 10))               -- 10
print(min("apple", "banana"))  -- apple
add(...) -> Int | Float

Returns the sum of all given arguments. An alternative to the + operator. Returns Int if all inputs are integers, Float if any input is a float.

print(add(7, 3))    -- 10
print(add(2, 3.0))  -- 5.0

// File I/O

Onload(path: String) -> String

Reads the full contents of a file at the given path and embeds it directly into the compiled binary. The file is resolved and loaded at compile time. If the file doesn't exist at the provided path, the compiler raises an error before a binary is ever produced.

tag content: String = Onload("data.txt")
print(content)

tag config: String = Onload("config.json")
print("Loaded:", content.size(), "bytes")

· Built-in Methods

Built-in methods are called on values using dot notation: value.method().

// String methods

String.size() -> Int

Returns the byte length of the string. For ASCII strings, this equals the number of characters.

tag s: String = "hello"
print(s.size())  -- 5
String.alter(old: String, new: String) -> String

Returns a new string with all occurrences of old replaced by new.

tag s: String   = "foo bar foo"
tag res: String = s.alter("foo", "baz")
print(res)  # "baz bar baz"

⚠ Deprecations

The following features are deprecated as of v0.4.0 and will be removed in an upcoming release.

⚠ Bool32 and String32 are deprecated. After performance research, 8-bit types were found to deliver stronger default performance compared to their 32-bit variants. Bool32 and String32 were introduced experimentally in v0.3.4 and will be removed in upcoming releases.

// What to do

  • Replace Bool32 with bool in all your code
  • Replace String32 with str in all your code
  • Int32 and Float32 are not deprecated — they remain valid 32-bit types
# Before (v0.3.4 — will break in future)
tag flag: Bool32   = true
tag name: String32 = "Dorpn"

# After (v0.4.0+ compatible)
tag flag: Bool = true
tag name: String  = "Dorpn"

? FAQ

Got a question not covered in the docs? Join the Discord ↗ or open an issue on GitHub ↗.

// What is Dorpn?

Dorpn is a compiled, statically-typed programming language with indentation-based syntax. It compiles to C — and as of v0.4.0, also to JavaScript — producing native executables via GCC. It is designed for developers who want clean, readable code without sacrificing execution speed.

// What platform does Dorpn run on?

Currently Windows only. The installer bundles everything you need — no separate GCC setup required. Linux and aarch64 support is on the roadmap for future releases.

// How do I install Dorpn?

Download the latest Windows installer from the Releases page ↗. Run it and Dorpn will be ready to use immediately. See the Installation section for details.

// How do I update to a newer version?

Download the latest installer from the releases page and run it — it will replace your existing installation automatically.

// Can I specify a custom output filename?

Yes, use the --out flag: dorpn program.dpn --out myapp. This has been available since v0.3.4. See the CLI Commands section for the full flag reference.

// What's new in v0.4.0?

v0.4.0 adds JavaScript compilation via -js / --Javs flags, the printOut() built-in for newline-free output, the void keyword for functions with no return value, and deprecates Bool32 and String32. Existing .dpn files compile as before with no changes required.

// Can I compile the same file to both C and JavaScript?

Yes — the same .dpn source file works with both backends. Compile without flags for a native binary, or add -js for JavaScript output. Note that some features may only be available in the native C target for now. See the CLI Commands section for usage.

// What does --verbose actually show?

--verbose (or -v) prints the first 20–25 AST tokens produced during the parse stage. It's most useful for diagnosing errors that occur early in compilation — syntax problems, unexpected tokens, and similar issues.

// Does Dorpn support lists or arrays?

Not in the current version. List and array support is planned for a future release.

// Does Dorpn have classes or structs?

Not yet. The current release supports functions, variables, and control flow. Object-oriented features are on the roadmap for future versions.

// What is the difference between -r and --run?

They are identical — -r is the short form and --run is the long form. Both compile the source file and immediately execute the resulting binary.

// Compilation fails with a syntax error — how do I debug it?

Run with --verbose to get early-stage AST output that can help pinpoint where the parser failed. For type-related errors, check that your variable types match — Dorpn is statically typed and catches mismatches at compile time. See Variables and Types for reference.

// Is the source code available?

Not yet. The compiler will be open-sourced once Dorpn reaches v1.0 or becomes self-hosted. Compiled binaries are available on the Releases page ↗.

// Where can I report bugs or request features?

Open an issue on the GitHub repository ↗ or bring it up on the Discord ↗.
